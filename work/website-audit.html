How I check whether a site is safe, fast and ready to ship, written down as a skill for Claude Code, with two scripts that need nothing installed.

The problem with most audits

Run a scanner over a site and you get a long list of warnings, most of them unverified. The one that matters is buried on page four, next to a complaint about a version number. I wanted audits I could act on, and could hand to a client without an hour of explaining.

So I wrote down how I check a site, then turned it into a skill for Claude Code: instructions, reference notes and two scripts that an AI assistant follows the same way every time.

Evidence, an honest ranking, a real fix

Every finding has to carry its evidence: a URL and header, a file and line, or a command's output. It says in one sentence who could do what, and gives the actual change to make, not "improve security".

Severity depends on the situation, not the name of the check. A missing content security policy on a static brochure page is low. On an admin that renders user content, it's high. Inflated ratings get a whole report ignored.

Each report also lists what's already done well, so nobody breaks it, and what wasn't covered, because an audit that hides its limits gives false comfort.

Two scripts, no dependencies

Both run on Python's standard library, so there's nothing to install and no supply chain of their own.

  • The external scan looks at a live site: redirects and certificates, security headers and the quality of the content security policy, cookies, third parties in the page, bundles and source maps, and email DNS.
  • The repository scan looks at the code: git hygiene, secrets, injection leads, dependency settings, build output, Docker and CI.

Their output counts as leads, not findings. innerHTML = '' is harmless and innerHTML = comment.body is stored XSS, so every flagged line gets opened and judged. No script finds a route that forgets to check who's asking, either, so access control gets checked by hand.

Careful with other people's sites

An audit touches live systems, so the rules come first. Anything beyond an ordinary page visit needs the owner's permission. Scans are passive by default, and active testing only happens on staging, when asked for. If a .env file is exposed, the report records its status and size and tells you to rotate what's in it: it's never downloaded or printed. An audit changes nothing; fixes are offered after you've seen the report.

Made for the Netherlands

Reference notes cover the usual stacks and hosts, OWASP, supply chain, performance and Dutch and EU compliance, such as Google Fonts loading before consent. Reports for clients come in plain language, in their own language. When the question is just "can I ship this?", it answers Go, Go with fixes or No-go, blockers first.
