An assistant I’m building to run entirely at home: language models on my own hardware, an agent layer on top, and three levels that decide what it may do without asking.

Why at home

Apollo is a personal assistant that runs on a server in my own house. The language models run locally through Ollama, so there are no per-token costs and my notes, calendar and code never leave the network. An agent layer on top gives the models their tools.

What it may do by itself

Every action falls into one of three levels, written down before any tool was connected:

  • On its own: read my notes and knowledge base, check the calendar, check GitHub and the servers, work inside approved project folders.
  • Asks first: send an email, change a calendar event, create a repository, push code, install software, change a server's configuration.
  • Only when told explicitly: delete files, repositories or databases, change the firewall, open a service to the internet, run anything destructive, touch sign-in or security settings.

The same rules go for how it reports back: it never claims something worked unless the tool confirms it, and it explains the failures that matter.

Where it stands

The models run on two Tesla P4 graphics cards in the home lab, split across both for 16 GB of video memory. Ollama and the agent layer start by themselves after a restart, the agent is reachable only from the machine itself, and a firewall lets through only what's needed. Backups of its workspace and configuration run on a timer, and so does a morning email with my calendar and the weather.

Next: reaching it safely from outside the house, most likely over a VPN rather than an open port; testing that the backups really restore; and a voice.
