Versteeg OS

This portfolio: an early-2000s desktop where every project is a program, and a phone home screen in your pocket.

The site you’re on. A desktop with windows, a taskbar and a start menu on a computer, a home screen on a phone, and a real website underneath both.

A portfolio you can poke at

Portfolios tend to look alike: a big headline, a grid of cards, a contact button. I wanted one you could play with, and my work suited the idea, because websites, a local AI and home servers are all things that run. So each project became a program on an early-2000s desktop, and every page became a window you can move, stack, minimise and close.

Nothing in it is borrowed. The start button carries a printer's registration mark, the grassland wallpaper is painted in code, and the interface is set in PT Sans, because the typefaces of the desktops it recalls can't be served from a website.

The colour belongs to the work

The frame stays out of the way so the projects don't have to look like it. Open a case study and its window takes on that project's palette and display face. Colours are stored as data and served in one generated stylesheet, and the admin refuses a palette that fails WCAG AA.

A real site under the costume

Without JavaScript, every icon is a link and every page is one window: the desktop is a layer over ordinary pages, not a replacement for them. With it, pages open as more windows on the same desktop, and the address bar follows the one in front.

The icons can be dragged and snap to a grid, and right-clicking the desktop offers to arrange them again. Where they are stays in your own browser.

On a phone it's a different machine

A desktop makes no sense on a phone, so below tablet width it turns into a phone home screen: the introduction as a widget, the projects as apps, a dock along the bottom, and pages that slide up full screen. Added to the home screen, it opens without browser bars.

Edited at home, published as files

The content lives in a small CMS with an argon2id password and a code from an authenticator app. That admin isn't on the internet. One command renders the real application to static files, and those are what you're reading now, on GitHub Pages. A list decides which projects go out, and the export stops if a project left off the list is still mentioned anywhere.

The content security policy travels with the pages, so scripts, styles, fonts and images can only come from this site.
