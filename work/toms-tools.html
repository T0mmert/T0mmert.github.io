My own dashboard: budget, scrum board, goals, habits and notes in one installable web app. It runs on static hosting with no server to trust, so the password itself had to become the lock.

The brief

A personal dashboard for the week: money in and out, a scrum board with timers, goals, habits and notes, plus the weather, the news and the calendar. It had to run without a server of its own, so it's static files on GitHub Pages, installable as an app and usable offline. The interface is in Dutch.

Where it started

The budget page began as a single HTML file: a neon terminal look, a pie chart and a line chart, savings goals and a twenty-step undo, all kept unencrypted in the browser's storage. Toms Tools kept the idea and rebuilt it with real categories, recurring bills and a cleaner data model, and dropped the neon.

A lock screen that means something

On a static site, a password screen that only hides the interface is worthless: anyone can delete the overlay in the browser's developer tools. So here the password is the decryption key. Every store is written to the browser's storage as AES-GCM ciphertext, with the key derived from the password through 600,000 rounds of PBKDF2. The key can't be extracted, and it lives in memory only while the tab is open.

Getting past the login screen without the password yields an app with nothing readable in it.

From the commit that added the lock

The password itself is never stored or hashed. The repository holds a salt and a short ciphertext. Unlocking means trying to decrypt it, which only succeeds under the right key, because AES-GCM is authenticated.

Data that repairs itself

Every store is validated and repaired as it's read. Before that, one malformed value could white-screen the app on every reload, with no way back. Imports go through the same schema, so a damaged backup can neither inject garbage nor blank existing data, and corrupt entries are set aside instead of overwritten.

Glass over a forest

The dashboard sits on a photo of a foggy pine forest (by Greg Zaal, from Poly Haven, CC0). The cards are glass: blurred, and refracted at the edges by an SVG displacement map inside the backdrop filter, so the trees bend at the bevel while the centre stays straight. Chromium shows the refraction; Safari and Firefox fall back to plain blur. The band at the top of this page uses the same filter.

Small things, fixed properly

  • Dates follow the local calendar. toISOString() had been stamping anything logged between midnight and 2 a.m. Dutch summer time with the previous day, breaking streaks and budgets.
  • The chart pages load on demand, which cut the first download from 206 kB to 69 kB of compressed JavaScript.
  • Focus rings everywhere, AA contrast for secondary text, and a drawer menu below 900 pixels wide, where the fixed sidebar used to take 62% of a phone screen.
  • Sync is optional and self-hosted: a dependency-free Node server with bearer tokens and constant-time comparison. Backups and pulls can't change the sync settings, so neither a file nor a compromised server can point sync somewhere else.
