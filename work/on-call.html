On Call

On Call

A game about fixing a failing server at 3 a.m., before the bakery’s 04:00 deadline. It runs in your browser.

Year
2026
Role
Design and build, personal project
Status
LivePlayable now, right here on the desktop.
Built with
  • TypeScript with no game framework
  • An engine with no page code, so it can be tested alone
  • Each night written as data
  • Runs entirely in the browser

Three nights on call at a made-up bread subscription. You get a terminal, a pager and a deadline, and every command costs minutes.

Play On Call. A night takes a few minutes, and you don't need to know anything about servers: there's a rubber duck for that.

Why a game

Most of what I can show about running servers is a list of things that didn't go wrong. That makes for a dull page. So instead of describing an incident, I made one you can have yourself.

You're the only engineer awake at Deegbus, a bread subscription I made up. At 04:00 the orders go to the bakery, and something is broken. Anyone can understand that deadline, even if they've never seen a terminal.

Mistakes are the fun part

Every command costs minutes, and the wrong ones cost more. Each trap comes from how real servers behave:

  • Delete a huge log file and the disk stays full, because the program writing to it still has it open.
  • Renew an expired certificate and the site keeps serving the old one until the web server reloads.
  • Block the noisiest network and you may cut off the bakery, which uses the same hosting company.

There's more than one way through each night, and shortcuts work just well enough to tempt you. Turn off certificate checks and the bread still arrives, but that goes on your report.

An incident report instead of a score

Points would have said very little. Each night ends with the document you'd write in real life: how long the outage lasted, whether you fixed the cause or only the symptom, and who you told. On the third night, fixing the servers isn't enough. You also have to wake the owner, who has a legal deadline to tell the regulator.

How it's built

The engine knows nothing about pages or about bread. It takes text in and gives a description of the night back, so the whole game can be tested without a browser. Each night is written as data on top of it, including the 600 random games the tests play to check that no combination of buttons leaves you stuck.

Computers get a real command line, with Tab completion and history. Phones get the same commands as buttons, which appear as you discover them. The terminal output and messages are marked up for screen readers, and the game can be played with only a keyboard.

Nothing you do leaves your browser. The commands are simplified and no real server is involved. It runs as ordinary files, under the same content security policy as the rest of this site.
